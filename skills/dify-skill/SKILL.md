# dify-skill 遛娃宝地 AI 服务

## 业务流程

```
用户提问 → 意图识别 → 调用对应 API → 返回结果 → 展示卡片
```

## 原子接口

| 接口 | 作用 | 组件 | 前置条件 |
|------|------|------|----------|
| askDify | 向 Dify 知识库提问 | answer-card | 用户提出了知识库相关问题 |
| searchPlaces | AI 语义搜索遛娃地点 | places-card | 用户想找遛娃地点 |
| searchNearby | 附近地点搜索 | places-card | 用户想查找附近的地点 |
| searchAmap | 高德地图 POI 搜索 | places-card | 需要高德地图数据补充 |
| searchMeituan | 美团美食搜索 | places-card | 用户想找附近美食 |

## 用户意图分流

### 直接意图（触发本 SKILL）

#### 地点搜索类
- "广州有什么遛娃的地方？"
- "推荐亲子活动场所"
- "附近有什么好玩的"
- "带孩子去哪里玩"
- "儿童乐园在哪里"
- "适合小朋友的地方"
- "周末遛娃好去处"

#### 附近搜索类
- "附近有什么遛娃的地方"
- "离我最近的公园"
- "3公里内有什么好玩的"
- "周边亲子活动"

#### 美食搜索类
- "附近有什么好吃的"
- "推荐餐厅"
- "想吃火锅"
- "附近美食"
- "附近有什么吃的"

#### 知识问答类
- "请问..."、"怎么..."、"什么是..."
- 产品咨询、政策问题、知识问答
- 客服类问题

### 意图分流规则

1. **地点搜索意图** → `searchPlaces`
   - 关键词：遛娃、亲子、好玩、推荐、去哪里、哪里好玩
   - 有位置信息时同时传入 lat/lng

2. **附近搜索意图** → `searchNearby`
   - 关键词：附近、周边、最近、3公里、5公里
   - 必须有用户位置信息

3. **美食搜索意图** → `searchMeituan`
   - 关键词：好吃、美食、餐厅、吃什么、饿了
   - 必须有用户位置信息

4. **知识问答意图** → `askDify`
   - 关键词：请问、怎么、什么是、为什么
   - 与地点无关的知识类问题

5. **闲聊/打招呼** → 不调用本接口，由 Agent 直接回复

6. **问题不明确** → 反问澄清
   - 例如："您是想找遛娃地点，还是想了解某个地点的信息？"

### 复合意图处理

当用户意图包含多个意图时，按优先级处理：
1. 如果同时包含"附近"和"遛娃" → `searchNearby`（带关键词过滤）
2. 如果同时包含"美食"和位置 → `searchMeituan`
3. 其他组合 → `searchPlaces`（综合搜索）

### 位置信息获取

调用搜索类接口前，应尝试获取用户位置：
```javascript
wx.getLocation({
  type: 'gcj02',
  success: (res) => {
    // 传入 lat: res.latitude, lng: res.longitude
  }
})
```
如果用户未授权位置权限，不传入坐标，由后端根据 IP 推断或返回全量结果。
